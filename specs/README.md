# Ecommerce Enabler Specifications

This repository follows spec-driven development. Production behavior MUST be
described by an approved specification before implementation changes begin.

## Workflow

1. Create or amend a specification.
2. Review goals, requirements, edge cases, and acceptance criteria.
3. Mark the specification `approved`.
4. Implement tasks referencing requirement IDs.
5. Verify acceptance criteria with automated or documented manual tests.
6. Record behavior changes in the specification change history.

Statuses are `draft`, `approved`, `implemented`, and `superseded`.
